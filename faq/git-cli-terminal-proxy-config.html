为什么命令行 git clone/pip 连不上代理？终端环境变量与 CLI 代理配置指南

✍️ 作者: 技术编辑部 ⏱️ 阅读时长: 5 分钟 📅 发布于: 2026-07-25 🔄 更新于: 2026-08-01

对于软件开发者、数据分析师和运维工程师而言，最常遭遇的技术尴尬莫过于：在桌面上打开了 Clash、V2RayN 或 Sing-box，浏览器访问 GitHub、HuggingFace 和 OpenAI 无比流畅，但在终端敲下 `git clone`、`pip install` 或 `npm install` 时，命令行却频繁报 `Fatal: unable to access: Failed to connect to github.com: Connection timed out` 错误。

为什么图形界面的系统代理对命令行完全不起作用？如何才能让命令行工具顺利通过本地代理节点访问外网？本文将为您透彻剖析 CLI 独立网络栈机制并给出最便捷的解决方案。

1. 为什么命令行忽略“系统代理”设置？

在 Windows 和 macOS 中，点击代理客户端的“系统代理（System Proxy）”开关，本质上只是向系统的全局网络设置注册了 HTTP/SOCKS5 端口（例如 `127.0.0.1:7890`）。

绝大多数带有图形界面的软件（如 Chrome、Edge、Spotify）在发起网络请求前，会自动向操作系统 API 查询系统代理配置。然而，像 `git.exe`、`python.exe (pip)`、`node.exe (npm)` 以及 `curl` 这样的命令行工具，设计初衷是运行在无图形界面的服务器终端，它们遵循 POSIX 规范或直接调用底层的 C Socket 库，默认完全无视操作系统的 GUI 代理注册信息。关于系统代理在不同层级的工作差异，可进一步阅读 系统代理工作机制与异常排查。

2. 方法一：设置终端环境变量（HTTP/HTTPS Proxy）

命令行工具通常读取标准的环境变量 `HTTP_PROXY` 与 `HTTPS_PROXY`。必须确认本地客户端监听的 HTTP 混合端口（以 Clash 默认端口 7890 为例）：

Windows PowerShell 脚本：

# 临时开启当前 PowerShell 窗口代理
$env:HTTP_PROXY="http://127.0.0.1:7890"
$env:HTTPS_PROXY="http://127.0.0.1:7890"

# 测试命令行网络连通性
curl.exe -I https://www.google.com

Linux / macOS Terminal (Bash / Zsh) 脚本：

# 设置临时终端代理别名 (添加至 ~/.zshrc 或 ~/.bashrc)
alias setproxy="export http_proxy=http://127.0.0.1:7890; export https_proxy=http://127.0.0.1:7890"
alias unsetproxy="unset http_proxy; unset https_proxy"

3. 方法二：配置 Git 专用代理规则

针对最高频的 `git clone` 失败问题，可以在 Git 的全局全局配置文件（`.gitconfig`）中单独写入代理选项：

Git 代理配置命令：
- 开启 Git HTTP 代理：`git config --global http.proxy http://127.0.0.1:7890`
- 开启 Git HTTPS 代理：`git config --global https.proxy http://127.0.0.1:7890`
- 仅针对 github.com 启用代理（推荐，避免影响国内 Gitee）：
`git config --global http.https://github.com.proxy http://127.0.0.1:7890`
- 取消 Git 代理：`git config --global --unset http.proxy`

4. 方法三：开启 TUN 模式实现全局无感接管

如果不希望每次打开终端都繁琐地输入环境变量或配置各个 CLI 工具，终极解决方案是开启客户端的 **TUN 模式（虚拟网卡模式）**。

TUN 模式直接在操作系统内核注册一个虚拟三层网卡，以最高的路由权值拦截全机所有的 IP 数据包。无论是什么命令行程序，无需任何代理配置即可自动被代理内核接管。关于 TUN 模式与 WFP 驱动拦截的深层技术原理，请参阅 TUN 模式与 WFP 驱动底层原理解析。

常见相关问题

为什么设置了 Git 代理后依然报 SSL certificate problem？
这通常是因为代理软件开启了 HTTPS 抓包或 SSL 扫描，导致 Git 校验自签名证书失败。可以通过命令 `git config --global http.sslVerify false` 临时关闭 SSL 校验，或参考 SSL 证书不受信任排查教程 正确导入根证书。
