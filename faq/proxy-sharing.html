局域网代理共享设置

✍️ 作者: 技术编辑部 ⏱️ 阅读时长: 8 分钟 📅 发布于: 2026-07-10 🔄 更新于: 2026-08-01

在日常工作、学习和娱乐中，我们经常遇到这样的场景：主力电脑（Windows 或 macOS）上已经配置并运行了顺畅的代理软件（如 Clash 或 v2rayN）。但是，身边的其他设备——例如不方便或无法直接安装客户端的 Switch、PS5、Xbox 游戏主机，或者是苹果电视盒子 Apple TV、智能电视，亦或是没有配置代理订阅的备用手机——同样需要访问国际网络。

此时，重新在每一台设备上购买订阅、下载客户端并导入节点不仅繁琐，有些设备在系统底层甚至根本不支持此类软件。最优雅、最省时且零成本的解决方案就是：**将主力电脑已经建立好的代理网络共享给局域网内的其他设备**。本文将基于网络运维实战经验，为您系统性地讲解如何在各大客户端中开启代理共享，并解决防火墙阻拦等经典硬核痛点，整理出这套 2000 字的 **局域网代理共享终极实操指南**。

一、 第一步：在代理主机端开启局域网允许

代理客户端默认为了主机安全，通常只监听 `127.0.0.1`（即仅限本地环回地址访问）。要想让局域网内的其他设备连进来，必须修改软件配置使其监听 `0.0.0.0`（允许所有局域网地址连接）：

  • 在 Clash Verge / Clash for Windows 中： 打开客户端的主界面，导航到“设置（General）”。找到“允许局域网（Allow LAN）”开关，将其开启。此时，开关下方会显示出本地监听的混合端口（Mixed Port），默认为 `7890`。
  • 在 v2rayN 中： 打开 v2rayN 主界面，在最下方的状态栏中，找到“允许来自局域网的连接”选项，将其双击切换为 `True`。记录下状态栏显示的 HTTP 代理端口，默认通常是 `10809`。
  • 获取主机在局域网中的真实 IP 地址： 开启允许局域网后，需要获取主机的内网 IP。在 Windows 系统中，按下 `Win + R` 键，输入 `cmd` 打开命令提示符，输入 ipconfig 回车。在输出中找到当前正在使用的网卡（无线局域网或以太网），记录下“IPv4 地址”，通常格式为 `192.168.x.x` 或 `10.0.x.x`。

二、 第二步：解决 Windows 防火墙阻拦的隐形障碍

很多用户在按照第一步设置后，尝试连接时依然显示“无法连接代理”或“连接被拒绝”。在 90% 的情况下，这并不是代理软件配置出错，而是 **Windows Defender 防火墙拦截了局域网内的入站流量**。

Windows 默认的安全策略会阻断外部 IP 访问主机的非必要开放端口（如 7890/10809）。解决方法是为代理软件手动开辟绿色通道：

  1. 在系统搜索栏输入“高级安全 Windows Defender 防火墙”并打开。
  2. 点击左侧的“入站规则（Inbound Rules）”，在右侧操作栏点击“新建规则（New Rule）”。
  3. 规则类型选择“端口（Port）”，点击下一步。
  4. 选择“TCP”，并在“特定本地端口”中填入您的代理端口（例如：`7890` 或 `10809`），点击下一步。
  5. 选择“允许连接（Allow the connection）”，点击下一步。
  6. 在配置文件页面中，勾选“专用（Private）”（建议取消勾选公用，防止在公共 Wi-Fi 环境下被他人扫描），点击下一步。
  7. 为规则命名为“代理局域网共享”，点击完成即可。
安全警告： 绝对不要直接关闭整个 Windows 防火墙，这会让您的电脑赤裸裸地暴露在各种内网扫描和蠕虫病毒攻击之下。通过上述“新建入站规则”仅开放特定端口，是最为稳妥安全的工业级解决方案。

三、 第三步：接收端设备的网络设置与调试

打通了主机的物理阻碍后，就可以配置需要上网的接收端设备了。确保接收端设备与代理主机连接在 **同一个 Wi-Fi（即同一路由器子网下）**：

1. 智能手机（iOS / Android）设置：
进入无线局域网设置，点击已连接 Wi-Fi 旁的“详细信息/配置”按钮。拉到最下方，找到“HTTP 代理”，选择“手动”。 在“服务器/主机”中填入代理主机的局域网 IP（例如 `192.168.3.15`），在“端口”中填入代理软件的端口（如 `7890`），保存。此时，手机上的所有浏览器和应用流量都将通过主机的代理节点转发出去。

2. 游戏主机（Switch / PS5 / Xbox）设置：
在主机网络设置中，选择当前 Wi-Fi，进入高级设置。将“代理服务器”选项从“禁用”改为“启用”。 同样填入代理主机的局域网 IP 与对应端口。这对于快速下载游戏更新、联机登入 Nintendo eShop 等场景极为实用。如果联机延迟仍偏高，可以阅读我们的游戏分析指南 [游戏加速优化排查](../topics/gaming-accelerator.html) 及 [延迟与丢包排查](../posts/why-high-latency.html)。

四、 进阶方案：TUN 虚拟网卡与软路由共享的抉择

传统的 HTTP 局域网共享存在一定的技术局限性：它只能代理支持 HTTP 协议的应用。许多主机游戏（基于 UDP 协议）或特定应用会直接绕过 HTTP 代理，导致依然无法联网。

如果您需要“无死角”的全局局域网加速，可以考虑以下进阶配置：

  • 在主机上开启 TUN 虚拟网卡模式： TUN 模式会在系统底层创建一个虚拟网卡，将所有的网络请求（包括 UDP 流量）强行进行三层路由劫持。在使用 Clash 时开启 TUN 模式，配合网络共享工具（如网卡桥接或三方分流软件），能够实现近乎完美的真全局局域网共享。具体的本地网关转发设置，可参考 路由器网关配置自救。
  • 部署软路由（OpenWrt）： 如果您家中的受网设备极多，频繁在每台手机和电视上修改 HTTP 代理 IP 极其不便。最佳的解决方案是部署软路由（如旁路由架构）。让软路由系统接管整个家庭网络的默认网关和 DNS 解析，实现全家设备插线上网即自动分流。关于这部分的深度配置指南，请详见我们的 [路由器 OpenWrt 系统固件设置](../topics/router-openwrt.html)。

五、 局域网代理共享常见故障排查

当配置好一切却依然无法上网时，请依据这套自救逻辑进行逐一排除：

  1. IP 变动引起连接失效： 路由器的 DHCP 机制会不定期重新分配主机的局域网 IP。如果主机 IP 从 `192.168.3.15` 变成了 `192.168.3.24`，接收端必须同步修改代理服务器 IP。为了根治此问题，建议在路由器后台将代理主机的 MAC 地址与特定 IP 进行“静态绑定”。
  2. AP 隔离（接入点隔离）冲突： 某些公共 Wi-Fi 或高端路由器的安全设置中开启了“AP 隔离（AP Isolation）”。此功能会禁止连接在同一 Wi-Fi 下的设备互相通信。如果是家庭路由，请进入路由器后台关闭此设置。
  3. 代理核心死锁与闪退： 主机的客户端后台核心如果因为未知原因发生崩溃，所有的共享连接都将瞬间断开。请检查主机的代理状态是否正常，并在遇到异常时，查阅 [系统代理残留与死锁排查](system-proxy-issue.html) 或是 [节点全挂紧急自救手册](all-nodes-down.html) 寻求恢复方法。

六、 自救逻辑清单总结

要成功开启局域网代理共享，请随时对照以下极简确认清单：
主机端开启 Allow LAN？ → 防火墙入站规则已添加？ → 获取到了正确的内网 IPv4？ → 接收端与主机在同一 Wi-Fi？ → 接收端手动填写了 IP 与端口？

只要满足以上五项条件，您就能彻底打通局域网内的设备屏障。如果您想进一步在多平台上优化代理客户端的使用体验，建议阅读我们的主流客户端详细教程，包括 [Clash Verge 教程](../guides/clash-verge.html)、[Loon 客户端配置](../guides/loon-guide.html) 以及 [v2rayN 调试流程](../topics/v2rayn-troubleshooting.html)。合理运用网络共享，能让您的多设备联动体验更加顺畅丝滑。
