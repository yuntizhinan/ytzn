浏览器提示 NET::ERR_CERT_AUTHORITY_INVALID 证书错误？SSL 信任与 MITM 修复

✍️ 作者: 技术编辑部 ⏱️ 阅读时长: 4 分钟 📅 发布于: 2026-07-25 🔄 更新于: 2026-08-01

在科学上网和配置代理软体时，许多用户经常在打开网页时遭遇红色警告拦截：“您的连接不是私密连接”，下方伴有错误代码 `NET::ERR_CERT_AUTHORITY_INVALID` 或 `SEC_ERROR_UNKNOWN_ISSUER`。此时几乎所有 HTTPS 网站均无法正常打开。

究竟是什么原因导致现代浏览器（Chrome、Edge、Safari）拒绝接受网络证书？本文将透彻解析 HTTPS X.509 信任链、中间人解密（MITM）原理，并指导您快速排查解决。

📍 本文目录
1. 错误诱因：MITM 中间人解密与自签 Root CA
2. 排查一：高级代理客户端 MITM 证书未信任
3. 排查二：杀毒软件 SSL 扫描与代理冲突
4. 排查三：本地系统主板 RTC 时钟不同步

1. 错误诱因：MITM 中间人解密与自签 Root CA

HTTPS 协议通过非对称加密算法（如 RSA/ECDSA）保障网络数据安全。浏览器连接 `https://google.com` 时，会严格校验服务器返回的数字证书是否由操作系统内置的极少数受信任权威 CA 机构（如 DigiCert、Let's Encrypt）颁发。关于 TLS 握手细节，可参阅 TLS 握手与 JA3 指纹伪装解析。

当您使用高阶代理客户端（如 Quantumult X、Loon、Surge 或 Stash）开启了 MITM (Man-in-the-Middle，HTTPS 解密重写) 功能以重写脚本或去广告时，代理软件必须在本地伪造目标网站的数字证书。若系统根证书库中缺少该自签 Root CA 的信任信任授权，浏览器就会触发防钓鱼拦截，弹出 `NET::ERR_CERT_AUTHORITY_INVALID`。

2. 排查一：高级代理客户端 MITM 证书未信任

如果在 iOS 或 macOS 设备上配置了重写规则，必须严格执行证书安装与完全信任两步曲：

iOS / macOS 正确信任 MITM 证书步骤：
1. 在代理客户端中点击【生成并导出 MITM CA 根证书】。
2. 打开系统【设置】- 点击【已下载的描述文件】- 点击安装证书。
3. 关键第二步：进入系统【设置】-【通用】-【关于本机】- 滑动至最下方【证书信任设置】。
4. 找到刚才安装的代理 Root CA 证书，手动勾选开启【完全信任】开关。

3. 排查三：杀毒软件 SSL 扫描与代理冲突

在 Windows 操作系统中，部分杀毒防护软件（如 360 安全卫士、Kaspersky 卡巴斯基、Avast）内置了“网页安全防护/SSL 扫描”功能。它们会强行拦截所有 outbound HTTPS 流量并重新加密。当杀毒软件的 SSL 过滤与 Clash / V2RayN 的代理逻辑发生重叠撞车时，就会导致证书签名链断裂报错。

解决办法： 在杀毒软件设置中暂时关闭“HTTPS 数据包扫描”或“WEB 脚本防护”功能。若为浏览器全局插件冲突，可参阅 系统代理开关与插件冲突排查。

4. 排查三：本地系统主板 RTC 时钟不同步

这是一个极易被忽视的硬件级原因：HTTPS 证书具有严格的生效时间（Not Before）与过期时间（Not After）。若电脑主板电池没电导致系统时间倒退回数年前，浏览器校验当前时间不在证书有效期内，便会误判证书无效。直接在 Windows【设置 - 时间和语言】中点击“立即同步”即可恢复。

常见相关问题

为什么关闭客户端 MITM 功能后，网页恢复正常？
如果不需要对特定 HTTP 报文进行重写或解锁，建议直接在客户端关闭 MITM / HTTPS 解密开关。普通代理（如常规 VLESS / Trojan 节点）本身是透传加密的，完全不需要开启 MITM 即可正常访问所有 HTTPS 网站。
