Clash Verge Timeout 报错深度解决：ETIMEDOUT 与连接超时终极排查

⚡ 快速解决 4 步走

  1. 检查本地时间：确保系统时间和时区准确无误，误差超过 2 分钟会导致 TLS 握手触发 Timeout。
  2. 更新并切换节点：在 Clash Verge 订阅列表点击“更新”，然后切换到非香港、非台湾的其他节点（如新加坡或美国）。
  3. 关闭 TUN 模式并重启核心：进入“设置”，临时关闭 TUN 模式，点击“重启核心 (Restart Core)”，看系统代理模式是否恢复。
  4. 更换网络环境：切换本地 Wi-Fi 为手机热点，排查是否为宽带运营商的墙中墙（如泉州白名单等）引起的 TCP 阻断。

一、问题表现：如何确认你遇到了 Timeout？

在使用 Clash Verge 时，如果遇到 Timeout 相关的错误，通常并不是软件本身的崩溃，而是底层网络连通性受阻。常见的表现为：

  • 节点测速全红：点击“延迟测试”后，所有节点全部显示 Timeout。
  • 连接日志报错：点击右下角“日志 (Logs)”面板，大量涌现 dial tcp: connect: connection timed out 或 ETIMEDOUT。
  • 网页无限加载：浏览器左下角提示“正在建立安全连接”或“正在解析主机”，等待很久后报错 `ERR_CONNECTION_TIMED_OUT`。

二、日志解读：常见错误代码的真正含义

根据 Clash Verge 日志中出现的具体字眼，排查方向大不相同。请不要把所有的“连不上”都当成同一个问题：

报错关键字 技术含义 可能原因
ETIMEDOUT TCP 连接超时 表示在规定时间内未收到服务器响应。可能是数据包在路由途中丢失、被防火墙拦截，或目标服务器无响应。
TLS handshake timeout TLS 握手超时 可能是 SNI 阻断、节点域名证书过期，或系统时间异常导致的证书校验失败等。
connection reset by peer 连接被重置 连接被重置。可能是网络审查（如发送了 RST 包阻断）、服务器端主动断开，或链路不稳定。

三、详细排查步骤：从本地到服务端

步骤 1：排查本地系统与网络

很多时候，Timeout 报错并非机场问题，而是本地环境导致的阻断：

  • 时间同步：前往 Windows 设置 -> 时间和语言，点击“立即同步”。TLS 握手对时间极其敏感。
  • 运营商层拦截：部分地区的移动或长城宽带存在“墙中墙”，会拦截未知 UDP 和非标准端口 TCP 流量。请使用手机数据网络开热点，连接后重启 Clash 核心进行测试。如果热点下正常，则说明是宽带运营商拦截。

步骤 2：排查 Clash Verge 软件配置

如果配置被污染或缓存卡死，也会导致局部 Timeout：

  • 重启内核：进入 Settings 面板，找到 Clash Core，点击右侧的重启按钮。
  • 重置系统代理：在 Settings 页面，临时将 System Proxy 关闭再重新打开。
  • 清理 DNS 缓存：在电脑终端中执行 ipconfig /flushdns，并清空浏览器的缓存数据。

步骤 3：排查节点与服务端状态

如果只有部分节点 Timeout，大概率是机场服务器问题或 IP 遭到了封锁：

  • 强制更新订阅：进入 Profiles 页面，右键点击你的订阅配置，选择 Update。有时机场更换了域名或端口，旧配置中的 IP 会导致 ETIMEDOUT。
  • 协议被识别：如果你在使用传统的 Shadowsocks 或 Vmess 且遇到 connection reset，说明协议可能已被 GFW 识别并封锁。此时应考虑更换提供新协议（如 Reality 或 Hysteria）的机场。

四、验证修复是否成功

完成排查后，请进行以下测试：

  1. 在 Clash Verge 的 Proxies 界面，点击右上角的测速图标。如果大部分节点从 Timeout 变成了带有毫秒数（如 120ms），则网络连通性已恢复。
  2. 打开浏览器，访问 https://www.google.com/ncr，如果能瞬间加载，证明系统代理正常。
  3. 查看 Logs 面板，确认不再大量滚动红色的 dial tcp 错误。

五、常见问题 (FAQ)

1. 为什么我的所有节点一瞬间全部 Timeout？

如果同一时间所有节点测速全部超时，最可能的原因是本地网络断开、系统代理冲突（例如开了其他 VPN 未关）或者是机场域名遭到 DNS 污染。建议更新订阅或切换热点测试。

2. Timeout 和 Connection Refused 有什么区别？

Timeout (ETIMEDOUT) 通常意味着数据包发出去后没有收到任何回应，犹如石沉大海，多为防火墙直接丢弃或 IP 被封。而 Connection Refused (ECONNREFUSED) 意味着服务器明确拒绝了连接，通常是因为对方服务器宕机或端口没开。

3. 为什么只有网页加载 Timeout，但 Telegram 却能用？

由于 Telegram 有自己的代理设置机制，而浏览器依赖系统代理或 TUN 模式。如果出现这种情况，请重点检查 Clash Verge 的 System Proxy 是否勾选，或者浏览器是否安装了代理插件（如 SwitchyOmega）并配置冲突。

4. 更换机场能解决 Timeout 吗？

如果是由于机场节点 IP 被批量封锁，或者使用了易被识别的老旧协议（导致被阻断），更换拥有专线（IEPL/IPLC）或抗封锁新协议的机场可能有助于改善或解决此问题。
