TUN 模式与 WFP 驱动底层原理解析：全局流量拦截、三层网卡重组与冲突排查

✍️ 作者: 技术编辑部 ⏱️ 阅读时长: 5 分钟 📅 发布于: 2026-07-25 🔄 更新于: 2026-07-25

在科学上网日常使用中，许多用户发现开启普通“系统代理”后，像 Steam 游戏客户端、Git 命令行工具、Node.js / Python 终端脚本以及 WSL 虚拟机依然无法连接外网。只有开启客户端中的 TUN 模式（虚拟网卡模式），才能实现真正无缝的全局网络接管。

究竟 TUN 模式在操作系统内核层做了什么？操作系统中的 WFP（Windows Filtering Platform）驱动又是如何工作的？本文将带大家深入 OSI 网络层与传输层底层，拆解 TUN / TAP 虚拟网卡数据包重组、LwIP 用户态协议栈转换、路由表 Metric 权值篡改以及常见网络冲突的定位解决之道。

1. OSI 分层视角：系统代理 vs TUN 模式

要理解 TUN 模式的强大，必须首先对比操作系统中不同代理模式的处理层级：

代理模式维度 系统代理 (System Proxy) TUN 虚拟网卡模式 (TUN Mode)
工作 OSI 层级： 应用层（Layer 7）：基于 HTTP / SOCKS5 代理协议。 网络层（Layer 3）：基于 IP 数据包的全局路由拦截。
流量接管范围： 仅限兼容 Windows Internet (WinINet) 或浏览器代理接口的应用。 全局所有应用程序：包含游戏、终端 CLI、DNS 查询、UWP 及 Docker/WSL。
协议支持度： 主要支持 TCP HTTP/HTTPS 流量，对 UDP 缺乏原生良好支持。 完美支持 TCP 与 UDP 全量数据包（支持 UDP Full Cone NAT 游戏联机）。
客户端配置门槛： 无需管理员权限，开关极其轻便。 需要系统管理员权限以安装虚拟网卡驱动与修改内核路由。

2. TUN 与 TAP 虚拟网卡的本质区别

在计算机网络中，TUN 与 TAP 是两种不同特性的软件虚拟网络设备（Network Virtual Adapter）：

  • TAP (Network Tap)：运行在 **OSI 第二层（数据链路层）**，模拟的是以太网网卡。它处理的是包含 MAC 地址、VLAN 标记的完整以太网帧（Ethernet Frames）。TAP 常用于 OpenVPN 或虚拟机桥接，开销较大。
  • TUN (Network TUNnel)：运行在 **OSI 第三层（网络层）**，模拟的是点对点（Point-to-Point）网络设备。它直接剥离了 MAC 地址帧头，仅接收并处理原始的 IP 数据包（IPv4 / IPv6 Packets）。

现代代理客户端（如 Sing-box、Clash Verge 和 Surge）均选择使用性能更优、开销更小、处理更简洁的 TUN 模式。

3. LwIP 协议栈与内核态/用户态数据拷贝

当操作系统内核将 IP 数据包写入 TUN 虚拟网卡后，这些数据包会被代理客户端的用户态程序读取。然而，内核发出的原始 IP 数据包只是无状态的字节流，代理软件必须将其重新解析为应用程序可识别的 TCP Socket 会话。

LwIP (Lightweight IP) 核心纽带： 代理客户端内部集成了一个嵌入式的轻量级 TCP/IP 协议栈——LwIP。LwIP 在用户态充当“虚拟操作系统内核”，负责将从 TUN 网卡收到的原始 IP 数据包进行重组，恢复出 TCP 三次握手、滑动窗口和 ACK 确认号，然后再将提取出的应用层数据交给 VLESS / VMess 协议 进行加密与远端转发。

4. Windows WFP 过滤驱动与路由表篡改机制

在 Windows 操作系统上，实现全局流量捕获主要有两种底层技术路径：

1. 修改系统路由表（Route Table Manipulation）

代理客户端通过 Windows API 创建一个虚拟 TUN 网卡（如 wintun 驱动），并向系统路由表中插入一条默认路由：`0.0.0.0/0 -> TUN 网卡 IP`，同时将该路由的 Metric（权值）设为极小（即最高优先级）。系统所有的出站 IP 数据包因此被强制引导至 TUN 网卡。

2. WFP (Windows Filtering Platform) 内核过滤驱动

WFP 是微软提供的内核级网络数据包过滤架构。高级客户端（如 Sing-box 的 `auto_route` 配合 `wfp` 驱动）会在 Windows 内核的 `FWPM_LAYER_ALE_AUTH_CONNECT_V4` 层挂载过滤钩子（Hook）。

当任何进程发起 Socket 连接时，WFP 驱动在数据包尚未到达物理网卡驱动前就直接将其拦截，并直接重定向至代理内核。WFP 驱动效率极高，且能够彻底防止应用程序通过绕过路由表（如绑定指定物理 IP 发包）造成的防封锁破口与 DNS 泄露（原理详见 WebRTC 与 DNS 防泄露设置）。

5. DNS 环路、网卡冲突与故障排查实战

开启 TUN 模式后，最常见的异常是“突然全面断网”或“网页无限加载”。这通常是由以下底层冲突引起的：

致命故障：DNS 死循环（DNS Loop）
代理客户端为了解析节点域名的真实 IP，自身也需要向 DNS 服务器发起查询。若客户端发起的 DNS 查询也被 TUN 模式的路由规则拦截并重定向回代理内核自身，就会形成“代理查 DNS -> 被 TUN 捕获 -> 再次查 DNS”的无限死循环。

核心解决方案与排查步骤：

  1. 配置 Direct 规则放行代理节点域名：在客户端 DNS 设置中，确保代理服务器域名（Server Address）通过本地物理网卡直连解析（Direct），避开 TUN 拦截。有关 FakeIP 与 Redir-Host 的深度原理，可参阅 FakeIP 与 Redir-Host DNS 架构详解。
  2. 设置 strict_route（严格路由模式）：在 Sing-box 或 Clash 中开启 `strict_route: true`。这会在内核中添加防火墙 DROP 规则，强制阻止除了代理应用本身之外的任何进程绕过 TUN 虚拟网卡。
  3. 排除局域网 CIDR 网段：避免 TUN 模式拦截 `192.168.0.0/16` 或 `10.0.0.0/8` 等私有网段，确保本地打印机、路由器后台和虚拟机能够正常访问。

常见问题解答 (FAQ)

TUN 模式与普通系统代理（System Proxy）有什么本质区别？ ▼
系统代理主要在 HTTP/SOCKS5 应用层工作，仅对主动读取系统代理设置的程序（如浏览器）有效，无法拦截命令行（cmd/git）、游戏客户端或 UWP 应用；而 TUN 模式是在操作系统内核注册一个三层（Network Layer）虚拟网卡，通过修改系统路由表将全机所有的 TCP/UDP IP 数据包无差别接管，实现真正的全局代理。
为什么开启 TUN 模式后会导致某些本地网络或虚拟机（VMware/Hyper-V）断网？ ▼
这是由于 TUN 模式在修改默认路由（0.0.0.0/0）时，将优先级（Metric 权值）设为极高，导致发往本地局域网（192.168.x.x）或虚拟网卡（172.x.x.x）的流量也被误拦截至代理内核。解决方法是在客户端中配置 strict_route: true 并正确排除局域网 CIDR 网段。
Windows 下 TUN 模式的 WFP (Windows Filtering Platform) 驱动有什么作用？ ▼
WFP 是 Windows 内核级的网络过滤平台。当代理客户端安装 WFP 驱动后，它能够在网络数据包离开物理网卡之前，直接在内核 Socket 层将其拦截并注入到 TUN 虚拟网卡中。相比传统修改路由表的方法，WFP 驱动能够彻底避免 DNS 泄漏与绕过物理网卡直接发包的恶意绕过行为。
