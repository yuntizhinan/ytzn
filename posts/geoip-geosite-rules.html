GEOIP 与 GEOSITE 规则库解析及机场防 DNS 劫持分流实战

✍️ 作者: 技术编辑部 ⏱️ 阅读时长: 4 分钟 📅 发布于: 2026-07-23 🔄 更新于: 2026-08-01
💡 摘要：网络分流是科学上网的核心体验指标之一。本文深入拆解 GEOIP（地理 IP 库）与 GEOSITE（域名分类库）的二进制数据打包结构与匹配流转逻辑，解决国内流量误走代理、国外网站被 DNS 污染等常见痛点。

一、 分流演进史：从繁琐的单条域名规则到二进制规则库

在早期代理工具（如 GFWList 时代）中，规则列表由几万条长长的域名文本组成（例如 DOMAIN-SUFFIX,google.com,Proxy）。随着互联网生态爆发，大型跨国公司（如 Apple、Netflix、Microsoft）拥有数以万计的子域名与 CDN 节点，使用纯文本进行逐行匹配不仅效率低下，而且会极大地消耗客户端 CPU 与内存。

为了解决这一瓶颈，社区推出了基于 Protobuf 二进制封装的 GEOSITE 和 GEOIP 规则库，将数百万条域名和 IP 段压缩为体积仅数兆字节的单文件，大幅提高了匹配效率与智能分流准确率。

二、 GEOIP 与 GEOSITE 的匹配协作机制

当客户端（如 Clash Verge 或 Sing-box）发起一个网络请求时，路由分流引擎会遵循严谨的优先级判定流程：

  1. Domain 域名阶段： 客户端优先检查请求的目标域名。首先匹配 geosite:private（局域网直连），其次匹配 geosite:cn（国内主流网站直连），再匹配 geosite:gfw / geosite:google 等代理规则。
  2. DNS 解析与 FakeIP 处理： 如果请求在 GEOSITE 阶段未命中任何显式规则，客户端会进入 DNS 解析阶段。配合我们在 FakeIP模式与DNS防泄漏原理 中介绍的技术，生成安全无污染的 IP。
  3. IP 阶段 (GEOIP 兜底)： 得到目标真实 IP（或客户端解析出的真实 IP）后，引擎调用 geoip:cn 进行匹配。如果是国内 IP，直接触发 Direct 路由；如果是国外 IP，触发 Proxy 路由。

这种“域名优先、IP 兜底”的双层防线，能够完美兼顾打开国内淘宝、微信的极致低延迟与访问海外服务的顺畅体验。

三、 避免分流失效与 DNS 污染的 3 大实战技巧

1. 禁用 Chrome / Edge 浏览器的“安全 DNS (DoH)”

许多现代浏览器默认启用了内建的“安全 DNS (DNS-over-HTTPS)”功能，这会导致浏览器的 DNS 解析绕过代理客户端的 TUN/FakeIP 接管，直接从浏览器内部发起 DNS 查询，从而打破 GEOSITE 的判定逻辑。建议在浏览器设置中将“使用安全 DNS”关闭，交由代理客户端统一调度。

2. 配置严格的防泄漏 WebRTC 规则

即使配置了精准的 GEOIP/GEOSITE 分流，某些基于网页 UDP 的探测请求依然可能泄露 IP。建议结合我们的 防止 WebRTC 泄露真实 IP 地址 教程，将相关检测点彻底封堵。

3. 选择具备原生 IP 与低延迟出口的高品质机场

精确的分流规则需要配合优质的底层节点。如 极连云 提供的 IPLC 专线节点，能够保证被分流到代理策略组的请求永远拥有纯净的出口环境。

四、 总结

深入理解 GEOIP 与 GEOSITE 的工作机制，能够让你不再盲目套用网上的“万能规则模板”，而是根据个人网络需求灵活配置无污染的科学上网路由系统。更多关于规则匹配的语法细节，可查阅 Clash与小火箭规则分流解析。
